# ASSAULT FRAME VS

アーケードのバーサス系 3D 対戦アクション（2機のロボットが射撃と格闘で撃ち合うタイプ）。ブラウザで動き、スマホのタッチ操作に対応。

**▶ 遊ぶ: https://yutianqiao7-dev.github.io/assault-frame-vs/**
（スマホのブラウザでそのまま動きます。ダウンロード不要）

モードは **CPU戦** と **通信対戦（スマホ2台）** の2つ。機体は12機、タイトル画面で自機を選べる。

### 通信対戦のつなぎ方

1. 両方で「通信対戦」を選び、それぞれ自分の機体を選ぶ
2. 片方が「部屋を作る」→ 4文字のコードが出る
3. もう片方が「部屋に入る」→ そのコードを入力して接続

繋がった時点で自動的に開始する。同じ Wi-Fi なら遅延は数ms程度。

```bash
npm install
npm run dev
```

`http://localhost:5174` を開く。`server.host = true` なので、同じ Wi-Fi のスマホから `http://<PCのIP>:5174` でも遊べる。

### 立ち回りの骨格

- **地上ブーストダッシュ**：地上でブースト＋方向を入れると、浮かずに地面を滑走する（速度 27 / 歩き 12）。押し続けて 0.5 秒経つとそのまま上昇に移行する。方向を入れずにブーストだけ押すと真上に上がる。
- ブーストボタンは**押しっぱなしで飛ぶ**。離すと落ちる。
- **着地するとブーストが全回復**するが、着地硬直が出る。この硬直を狙う／狙われるのがこのジャンルの核。着地すると地上ダッシュ枠もリセットされるので、**着地→即ブーストでまた地面を滑れる**。
- ブーストを使い切ると**オーバーヒート**。空中なら強制落下＋着地硬直（1.15秒）、地上ならその場で同じだけ硬直する。
- **ステップは行動をキャンセルできる**（射撃硬直・格闘の振りをキャンセル）。ブーストを固定量消費する。
- **格闘もブーストを食う**。踏み込みに固定コスト（`meleeCost` 14）＋突進と振りの間は毎秒消費が続く。N格1段で約 30、3段フルコンボで約 61。ブーストが足りない／オーバーヒート中は格闘を出せないので、**コンボを完走すると着地を晒すことになる**。
- **ステップは誘導も切る**。自分に向かってきている敵弾の誘導が消えるので、飛んでくるタイミングに合わせてステップすれば射撃はまず当たらない。**このゲームの防御の要**。逆に、垂れ流しの射撃は当たらない。
- **ビルには当たり判定がある**。壁で止まり、屋上に着地でき（着地扱いなのでブーストも回復する）、射線も遮る。ビル越しに撃った弾は壁で消えるので、遮蔽を使って射線を切れる。CPU も射線が通っていなければ撃たない。
- 先行入力バッファ（0.35秒）があるので、硬直中に押しても受け付ける。

## 実装済みのシステム

- **ブースト / 地上ブーストダッシュ / ステップ / 着地硬直 / オーバーヒート**
- **ビルの当たり判定**（`src/collision.js`）：AABB との押し出し・屋上への着地・線分判定による射線と弾の遮蔽。ビルは必ず地面から生えた軸沿いの箱なので、横の押し出しを先に解決すれば「足元にある屋上」を見るだけで床が決まる。
- **撃墜演出**：最後の1機を落とすと、すぐリザルトを出さずに **ヒットストップ → スローモーション → 寄りのカメラ → 爆散 → リザルト**（約2.8秒）を見せる。通常の撃墜にも短いヒットストップが入る。
- **一時停止**：戦闘中に左上のボタン（または Esc）で停止し、そのままメインメニューへ戻れる。リザルト画面にもメインメニューボタンがある。
- **通信対戦**：WebRTC の P2P。**ホストが両機をシミュレーションし、ゲストは入力を送って結果を描画する**（`src/net.js` / `src/netsync.js`）。
- **ロックオン**：常に敵を向く。カメラは自機の後方から敵を含めて捉える。
- **武装**：弾数・リロード・クールタイム・偏差射撃・誘導。ビーム／実弾／砲弾／拡散／ミサイル／照射ビーム／ファンネルの7タイプ。
- **格闘**：接近（ラッシュ）→ 連撃。**N格 / 横格 / 前格**の3派生があり、段数もダメージも別物。踏み込みと突進・振りでブーストを消費する。
- **ダウン値**：合計 5.0 で強制ダウン。1.6 秒被弾しないとリセット。強制ダウンは大きく吹き飛ばすので、密着で撃ち続けることはできない。
- **ダウン追撃**：倒れている相手にも当たるが、ダウン時間は延長されず、浮かせ直しもできず、ダメージは 0.32 倍。起き上がりには無敵が付く。
- **よろけの蓄積**：射撃はダウン値が 1.0 たまるごとによろける。マシンガンのような軽い弾は毎発のけぞらせない（格闘は常によろける）。
- **コンボ補正**：ヒット数に応じて 1.0 → 0.85 → 0.74 …（`COMBO_SCALE`）
- **覚醒**：与ダメ・被ダメでゲージが溜まる。発動でブースト全回復＋移動 1.22 倍・与ダメ 1.13 倍を 9 秒。
- **戦力ゲージ（コスト）**：両陣営 6000。撃墜されると機体コスト（2000）を引かれる。0 で敗北。
- **CPU**：EASY / NORMAL / HARD。距離取り・横移動・被弾回避のステップ・格闘・覚醒。難易度で反応速度と**射撃精度**（`aimError`）が変わる。

### 格闘の派生

どの機体も **N格闘 / 横格闘 / 前格闘** の3系統を持つ。スティック（またはキー）の入れ方で出し分ける。

- **N格闘** … 標準。段数が多く総ダメージが高い
- **横格闘** … 回り込みながら接近する。射線をずらせるぶん、段数は少なめ
- **前格闘** … 突進が速い。段数は少ないが1段が重い

段数・ダメージ・ダウン値は機体ごとに違う（例: ノクスのN格は4段、テンペストの前格は1段115ダメージ）。

モデルはプリミティブ（面取りした箱・円柱・球）から `src/mechmodel.js` で組んでいる。差し替え前提。

### 見た目まわり

- **ブルーム**（`UnrealBloomPass`）でビーム・サーベル・スラスターを発光させている。しきい値 0.86 で発光体だけ拾い、機体や地面はにじませない。スマホではブルームの内部解像度を半分にして塗りつぶし負荷を 1/4 にしている。
- **発光体は「白熱コア＋色付きグロー」の二層**（`src/glow.js`）。加算合成 + `toneMapped:false`。単色の不透明メッシュのままだと、ブルームを掛けてもただの明るい棒にしか見えない。
- **閃光・爆発はスプライト**（中心が白く外へ消えるグラデーション）。球メッシュだと輪郭が硬く「玉」に見える。
- **サーベルの軌跡**は直近7フレームの刃先を三角ストリップにしたリボン（`Trail`）。刃の根本から引くと巨大な扇になって画面を覆うので、外側 38% だけを引いている。
- 機体は**面取りした箱＋パネルラインのテクスチャ＋装甲/関節/小物のマテリアル3階層**。装甲の内側に一段細い暗色フレームを入れて板の重なりを見せている。
- **リムライト**（背後やや上＋逆サイド）で輪郭を背景から切り離している。これが無いと暗い背景に暗い機体が沈む。

## 開発メモ

- `window.__dbg` にゲーム内部を出している。
  - `__dbg.step(dt)` … 1 フレーム進めて描画（rAF が止まっていても手動で進められる）
  - `__dbg.sim(n)` … 描画せず n フレーム進める（対戦のシミュレーションに使う）
  - `__dbg.game` / `__dbg.world` / `__dbg.chase` …
- 開発サーバーに `POST /__shot/<name>` がある。base64 の JPEG を投げると `.shots/<name>.jpg` に保存する（プレビューが見えない環境でのレンダリング確認用）。
- `preserveDrawingBuffer` と `window.__dbg` は `import.meta.env.DEV` で囲ってあるので、本番ビルドには入らない。

### 通信対戦の設計

**ホスト権威**にしている。両者が独立に同じ計算をする方式（ロックステップ）は、
今のシミュレーションが `Math.random()` を各所で使っていて決定的ではないため成立しない。

- ゲストは毎フレーム自分の入力だけを送る。**エッジ入力（格闘・ステップ等）は真偽値ではなく「押した回数」を送る** — 送信側と受信側のフレームがズレたときに取りこぼしたり二重に出たりしないように、ホストは差分を1フレーム1回ずつ消化する。
- ホストは 30Hz で全状態を送る。機体1体が23個の数値、スナップショット全体で約 300 バイト（**約 9KB/秒**）。
- ゲストはスナップショットの間を速度で外挿し、受信時に 0.4 の重みで補正する。
- 当たり判定・ダメージ・勝敗はすべてホストだけが決める。ゲスト側の弾は見た目だけ。
- 被弾エフェクトはゲスト側で HP の減少から推測する（別メッセージにしない）。

**既知の割り切り**：ゲストは自分の操作にも往復ぶんの遅延を感じる（同じ Wi-Fi なら数ms〜数十ms）。ロールバックは入れていない。

### 撃墜演出の作り

`main.js` の `finishSeq`。**演出そのものは実時間で進み、シミュレーションだけが `timeScale` で遅くなる**（`tick(dt * timeScale)`）。

| 時刻 | 内容 |
|---|---|
| 0.00〜0.14秒 | `timeScale` 0.06。ほぼ静止させて当たった重さを出す。白フラッシュとバナー |
| 0.14〜1.45秒 | 0.24 のスローモーション。カメラが倒された機体に寄って回り込み、爆散と破片、0.2秒おきに追い討ちの小爆発 |
| 1.45〜2.35秒 | 等速へ戻しながらカメラが引く |
| 2.75秒 | リザルトをフェードイン |

- 撃墜された機体は **0.32秒ぶんだけ残骸として残る**（`DEAD_SHOW`）。即座に消すと、寄ったカメラが何もない地面を映すことになる。スロー中なので体感では1.5秒ほど見えている。
- 衝撃波は**細い輪**（`RingGeometry(0.975, 1.0)`）。太い輪を巨大化させると、寄りのカメラではただの白い帯になって画面を覆う。
- 通信対戦ではホストが `fin` を送り、**両者が同時に自前の演出を回す**。結果はゲスト側で反転する。遅れて届く `end` は演出中なら無視する。

## クレジット / 権利について

機体名・武装名・タイトルはすべてオリジナル。3D モデル・コード・UI もすべてこのリポジトリ内で自作（外部アセットの取り込みなし）。依存は three.js と Vite のみ。

ジャンルとしてアーケードのバーサス系 3D 対戦アクションを参考にしているが、特定作品の名称・意匠・アセットは使用していない。
